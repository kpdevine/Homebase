# Quick reactions, compact profile editor, and username changes

The owner requested whole-message vibes taps, top-right reaction badges, no scrolling through reaction choices or the planet/vibes editor, editable available usernames, and a small anchored reaction bubble similar to iPhone messages. A final refinement asked for emojis large enough on a small iPhone.

Tapping a day score or anywhere on a nonblank vibes message opens an anchored, nonmodal reaction bubble. All 22 planets are visible together: six columns on ordinary phones, five on screens at most 350px wide. The 320 × 568 sample showed roughly 44px-tall emoji artwork and all choices inside the viewport. The bubble prefers the space above its target, stays inside the visible viewport, and can use the space below when needed. Outside taps and Escape dismiss it. Choosing the current reaction removes it. Counts remain visible, with names available through accessible labels and hover text. Day details remain available through the secondary View day action. Existing verified reaction push behavior is unchanged.

Vibes use a button across the entire message surface, with a separate author Edit action. Reaction badges sit at the top right, with counts for repeated planets. They wrap without covering the text. Score reaction badges also use the top-right corner.

My planet & vibes places the text field, every planet choice, and Save in one compact sheet. The grid and text field size adapt to the visible viewport, including keyboard space. Phone checks at 320px and 390px widths showed no dialog scroll; a 390 × 352 limited-height check also fit the field, all planets and Save. Arrow keys move across the eight-column profile grid. Saving still uses the private preferences record and preserves the existing vibes version behavior.

Solar Systems now offers Change username. The existing 3–20 character validation applies. One Firestore transaction reserves an available handle, changes only the profile username, and releases the previous handle. Created-at timestamps and UID-based records, friendships, memberships, statuses and scores remain attached to the same account. A failed/taken-name transaction leaves the previous name intact. Rules prohibit profile-only renames, deleting the current handle without a replacement, touching another account, or taking an occupied name. Friends and group boards resolve current names from live public profiles. Admission reads the current profile, so renaming while a join request is pending does not break acceptance.

Validation: 265 regular tests, 264 passed and one emulator-only skip; all 11 backend tests passed. The Firestore emulator suite passed with new occupied-name, concurrent-race, old-name release/reuse, identity/timestamp preservation, foreign-owner rejection, live friend/board updates, and pending-request rename cases. Disconnected browser samples verified both reaction bubbles, all choices within the small-phone viewport, selecting/removing reactions, whole-vibes taps, the compact editor and saving both fields, taken-name feedback and a successful sample rename. No production personal records, reactions or usernames were changed for QA.
