# Current vibes reactions and push alerts

The owner requested notifications for existing day-score reactions and confirmed that Current vibes should also support reactions. A later clarification requested the same emoji interaction as day scores.

Every nonblank Current vibes message has a **React to vibes** action for other members and **View reactions** for its author. It opens the same four-column planet picker and reaction/name presentation used for day scores. A person has one reaction per status; choosing the same planet again removes it. Changing the vibes text creates a new version, so previous reactions do not appear on the new message. A planet-picture-only edit retains the version. Existing messages without a version remain usable as legacy statuses.

After a reaction commits to Firestore, the signed-in reactor requests an immediate push through the existing notification Worker. The Worker verifies the Firebase ID token, reads the actual saved reaction using that token and the existing member-only rules, checks current membership, and checks that the reaction is fresh and still points to the current status. Recipient, username, kind and status version are derived from verified documents; client-supplied reaction text or recipient push endpoints are never trusted. No administrator credentials or private day records are needed.

Alerts go only to the recipient's existing registered devices and work independently of daily reminder eligibility. Self-reactions, deletions, stale statuses, unauthorized users and historical reactions do not generate alerts. An atomic D1 claim deduplicates concurrent/repeated requests and sends at most one alert per reactor and status/day; changing the emoji or removing/re-adding it does not send repeated alerts. New events are limited to 20 per reactor per ten minutes. Claims contain only an event hash, actor ID and creation time, retained for 40 days. Expired devices are removed; uncertain sends are not automatically repeated.

Push text names the reactor and planet reaction, without copying status text, score values or private logs onto the lock screen. Tapping opens Solar Systems. The push service worker accepts only the app's exact Solar Systems link. Settings now describes both reaction alerts and the daily reminder under Notifications, with the existing enable/disable controls. Existing subscriptions are reused and the service worker checks for an update once when the app opens.

Validation: 265 regular tests (264 passed, one emulator-only skip), 11 backend tests passed, and the Firestore emulator security suite passed separately. New coverage verifies token/permission enforcement, current-version checks, committed-write-before-alert ordering, recipient-only routing, parallel request deduplication, changes/removal, rate limits, expired subscriptions, client retries, and safe notification navigation. Disconnected browser samples verified sending/removing a reaction, names/counts, new-status isolation, no self picker, the same day-score picker sizing, and a 390px phone layout. No production reactions, statuses or private day records were created for QA.
