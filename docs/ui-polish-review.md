## Change log

- **UI-01 — Common contrast, type, and control states.** Use shared dark ink, brighter field surfaces, pale secondary buttons, dark primary actions, consistent selected states, visible keyboard focus, and dark-backed late-warning symbols. Native form controls use the existing LCD fonts; handwriting fields retain Kieran's font. Completed task text stays readable. The retro blue palette, scanlines, meter rewards, and font assets remain. Revert the UI-01 block and shared form rules in `cohesion.css`.

- **UI-02 — Consistent headings, content edges, and wording.** Bold every main page title; align detail content to the same outer edges; normalize heading/action spacing; keep all three planning-card titles aligned below their date; allow safe heading wrapping. Phone greetings reserve the same height across pages and clamp long names to two lines. Use “To-do list” in recaps and “Sentiment rating” consistently, “Remove rating” for both rating-removal controls, and correct singular “subtask.” Task progress calls counted leaf checkboxes “actions,” reflecting the existing scoring rule. Sources: UI-02 CSS, `renderTasks()`, `recapMarkup()`, and labels in `index.html`.

- **UI-03 — Accessible phone navigation and reliable section switching.** Keep the five daily tabs sticky when scrolling. Normal portrait phones use one compact row; narrow phones use two rows to keep labels legible. Retain numbered tabs and clear review checks. Add a 6px inset at both phone tab-row ends so the outside borders and keyboard focus outlines have room. Switching sections reveals the beginning of that section instead of retaining an unrelated scroll position. Remove the old attempt to access a nonexistent Achievements tab, which could throw on phone. Sources: UI-03 CSS and `setView()`.

- **UI-04 — Compact saved weight with a deliberate editor.** Keep the saved body weight prominent on Daily training, with “Log weight” or “Edit weight” opening the entry controls. Saving closes the drawer and focuses its summary. An open draft survives other training renders, displays “Unsaved weight · choose Save weight,” and delays incoming cloud application until the editor closes. Closing without saving restores the saved value. This reduces the always-expanded form while preserving explicit saving. Sources: `weightEditor` initialization/toggle, `renderGym()`, `updateWeightDraftHint()`, weight submit/unit handlers, cloud `canApply`, and UI-04 CSS.

- **UI-05 — Training priorities and optional detail.** Show the ideal workout before the set logger. Keep weekly muscle deficits under “Weekly muscle gaps” rather than displaying a second expanded recommendation panel. Training notes open on demand and start expanded for dates with existing notes. A logged rest day hides the ideal-workout recommendation; weekly progress remains available. Compact the attendance/score/weight areas and weekly rest summary. Sources: initialization of `gapsDetails`/`notesDetails`, `renderGym()`, and UI-05 CSS.

- **UI-06 — Readable recap metrics.** Place the score denominator/set count below the main number, permit wrapping, and fit category metrics to their column so labels and numbers cannot collide. Keep archived metrics readable while disabled. Use a visible border on calendar dates and legible, dashed neighboring-month dates; replace the obsolete ring-description legend with the logged-day marker meaning. Sources: UI-06 CSS and calendar legend in `index.html`.

- **UI-07 — Consistent dialogs and editable fields.** Use a shared readable dialog surface, sticky heading and reachable 44px close control, wrapping action rows, and a visible final-review footer. Keep the final sentiment circle beside its notes except on the narrowest screens. Apply the same background to task/subtask fields and theme the backup file button. Set mobile date/profile/select text to 16px to avoid the usual small-font focus zoom on phones. Sources: UI-07/shared form CSS and the stylesheet link in `index.html`.

- **UI-08 — More useful mobile space.** Use a compact side-by-side score card on portrait Overview, shorter note editors, a tighter training layout, and two-column weekly muscle progress. Landscape places Nutrition and Sentiments controls beside their notes, keeps the training day/week side by side, and places the three planning cards in columns. Achievement cards use two portrait columns and three landscape columns; their category tools stay accessible. Content with genuine length still scrolls. Source: UI-08 and phone/landscape blocks in `cohesion.css`.

- **UI-09 — Compact, explicit review controls.** Group the step checks, confirmation action, readiness hint, and pause action in a single smaller review box. Hide the duplicate detail heading while guided review is active. Keep the review box sticky on taller phones/tablets, but let it scroll on short landscape screens. Compact the past-day notice while retaining its date and Return to today action. Source: UI-09 CSS.

- **UI-10 — Phone/tablet calendar selections reveal their recap.** Selecting a date scrolls to its summary and focuses it; “Back to calendar” returns to the month. Filters and month navigation do not unexpectedly jump to the recap. Long recap notes/task lists are constrained rather than making the entire calendar page arbitrarily tall. Desktop keeps its side-by-side behavior. Sources: `phoneLayout()`, calendar click handler, `back-to-calendar` initialization, and UI-10 CSS.

- **UI-11 — Tablet and scrollbar consistency.** Intermediate tablet widths use normal document scrolling instead of a fixed desktop pane squeezed above an oversized footer. Keep the score compact, use the available columns for training/planning/achievements, and let the clock footer follow the overview content. Reserve scrollbar space on compact layouts so header controls do not shift when moving between short and long pages. Source: UI-11 and scrollbar CSS.

- **UI-12 — Settings without a permanent animation sample.** Hide the LCD motion sample until Preview is requested or animations are turned on. Hide it again when motion is reduced and on the next Settings visit. Put the reference-only display description under “About this display.” Cloud, backup, and reset controls remain directly available. Sources: Settings markup, `openSettings()`, `renderMotionSetting()`, motion change/preview handlers, and UI-12 CSS.

- **UI-13 — Reliable graph point selection.** When enlarged point hit areas overlap, pick the nearest visible dot instead of whichever SVG element happens to be last. Mouse movement updates between nearby points; pointer selection focuses the selected reading. Keep keyboard activation, touch pinning, tap-away dismissal, the compact in-app card, signed previous-day weight change, and accessible labels. No browser tooltip is reintroduced. Sources: `nearestWeightPoint()` in `weight-history.mjs`, graph pointer handlers, and `tests/weight-history.test.mjs`.

- **UI-14 — Deleting sets preserves the lifting answer.** Removing the last set entry leaves “Yes, I lifted” selected, earning the existing 4-point attendance baseline and consuming no rest credit. Choose No explicitly to record rest. Historical set deletion still reclassifies later goal/non-goal sets and reopens affected reviews. Explain why No is disabled while set entries remain, with a hint shown only in that case. Sources: `removeGymEntry()` in `model.mjs`, training markup/rendering/removal announcement, and the updated display-model/training-pace tests. **This is the substantive gym behavior change in this pass.**

- **UI-15 — Matching info icon and a grouped scoring guide.** Replace the round letter button with a 40px square SVG icon matching Home, Calendar, Achievements, and Settings. Group Gym's formula, goal/non-goal sets, rest credits, worked example, weekly rules, and body-weight explanation under one Gym heading. Nutrition, To-do list, Sentiments, and logging/review each have their own section. This reorganizes the explanation without changing scoring. Sources: `index.html` info symbol/button/dialog and UI-15 CSS.

- **UI-16 — Two useful streak types.** Show only consecutive days with all three required categories logged and consecutive completed days scoring 9+. Keep current/best counts and existing milestone thresholds for those two types; remove the redundant day-review streak cards and their six icons. The catalog now contains 49 achievements. Day-review total milestones remain. Streaks continue to derive from saved history without storing a separate ledger. Sources: `achievements.mjs`, `renderAchievements()`, `achievements.css`, `achievement-icons.mjs`, and achievement tests.

- **UI-17 — Phone checkbox alignment and fixed writing frames.** Align 20px phone/tablet checkboxes to the first text line's cap height, including wrapped names, recurring labels, and children. Task/subtask fields use a fixed writing frame plus transparent overflow space for the owner's long descenders. Measure wrapped line boxes with a hidden text mirror instead of using glyph-inclusive textarea scroll height. Descenders cross the underline without growing its frame or moving the next control; actual wrapping still adds lines. Sources: task name/subtask wrapper markup, `fitTaskField()`, and UI-17 CSS. Kieran explicitly requested this fix and publication after approving the broader pass.

- **UI-18 — Safer recurring removal.** The manager filters stopped/expired schedule versions out of both its list and count, retaining history. Stopping a schedule or removing one recurring occurrence opens a confirmation with the task name and exact scope. Cancel is initially focused. One-time removal retains its existing Undo. Sources: `activeTemplates()`, task removal/stop handlers, shared removal dialog, and onboarding/recurrence tests.

- **UI-19 — First-visit welcome.** New personal visitors choose a name or the existing Google sign-in flow. Name entry persists and personalizes the greeting; Google can use its account display name. Preserve pending onboarding across same-tab Google redirects. Existing records, named visitors, previews, and recovery bypass welcome. Sign-in does not enable uploads. Sources: `onboarding.mjs`, Welcome markup/styles/handlers, `cloud-ui.mjs` shared sign-in method and auth callback, and onboarding tests.

- **UI-20 — Prefer newer saved versions in cloud sync.** Persist per-record edit times tied to saved payloads, carry them through existing cloud payloads, and automatically resolve competing live records by newer known edit time. Newer local records upload; newer cloud records are adopted. Preserve manual decisions for unknown/equal/future times and deletion conflicts, and compare timestamps as well as payloads inside transactions. Only saved local data is eligible for upload while a newer typing draft is pending. Explicit local conflict choices get a fresh decision timestamp. Sources: `record-edits.mjs`, cloud engine/driver/UI integration, local save hooks, and `tests/smart-sync.test.mjs`.
