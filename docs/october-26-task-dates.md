# Task creation and list rebuild — approved release

The owner reviewed the local draft and approved publication with “push it” on October 27, 2026. Deliver matching source and Firebase Hosting; this release needs no Firestore rule changes.

Task creation and editing show Due date first as a required calendar input, defaulting to today for a new task. Choosing a different due date reveals Plan to work (optional), using an identical calendar input. Choosing today again hides and clears the planned date. There are no date shortcut buttons or separate date-selection disclosures. Without a planned date, the task appears immediately and carries until completed, including overdue dates. A planned date delays its first appearance until then. Existing dated tasks without deadlines retain their prior records and behavior; editing one supplies the new required deadline. Planned dates keep the seven-day planning window, while deadlines can be farther in the future. Recurring occurrence edits retain their scheduled day.

Separate Due and Plan date bubbles appear in Overview, To-do, planning cards and recaps; Plan is omitted when no work date was selected. Both glow, and past dates glow red while unfinished in either theme. Completed tasks lose the overdue warning. Future planning cards compare against today to avoid early warnings. Due today and Overdue have explicit labels; dates in another year include the year. Names and bubbles wrap within narrow columns without overflow. Later This Week shows carried tasks once on their planned date; Tomorrow previews tasks expected to remain open.

The latest visual refinement makes all date bubbles smaller (9px type and 2px by 5px padding) with proportionate glows. Due dates use a filled pill; planned dates use a transparent, dashed rounded rectangle. The distinct shapes remain when overdue dates glow red.

The owner's button-coherence follow-up standardizes the three planning-card actions to full-width “+ Add task” buttons with matching height, type, borders and fill. Task and planned-task pencils share sizing and hover treatment. Due date and Plan to work use the same full-width input style and calendar affordance, with a minimum height of 44px. Repeat choices retain consistent selection styling; Save remains the primary action. Settings explains the due-today default and retains the expanded-subtask preference.

Existing subtasks, recurrence frequencies, occurrence/future editing, removal and Undo remain. Recurring deadlines follow the same day offset on each occurrence. Carried tasks are stored once in their original day record, with a bounded ordered list of dated task states. Read-only daily projection preserves prior names, checks and deadlines; completing later does not mark earlier days completed. All write paths discard transient projections while retaining their original record. Editing an old pending task from a current day is supported without unlocking archived dates.

Validation preserves the optional fields in version-2 backups and private cloud payloads, validates event states and prevents sequential-ID reuse through removed historical subtasks. Existing Firestore record types, permissions and rules remain unchanged. Achievements read the displayed dated state and deduplicate carried actions. Changes reopen affected future list reviews without touching earlier reviews.
